# ⏱️ Scheduling Service — Multi-Horizon Engine

> **Module Path:** `lib/services/scheduling/`
> **Owner:** Core Engineering Team
> **Priority:** Critical

---

## Purpose

The Scheduling Service implements the **three-horizon scheduling model** mandated by Indian Railways, managing the 26-week Rolling Block Programme (RBP) and dynamically refining it down to daily operational schedules.

---

## Three Horizons

### Strategic Horizon — 26-Week Rolling Block Programme (RBP)

| Attribute | Value |
|-----------|-------|
| **Time Span** | 26 weeks (rolling, updated weekly) |
| **Update Cycle** | Every Monday, append 1 new week |
| **Content** | Major works: track renewals, bridge rehab, EI commissioning, large-scale OHE replacement |
| **Approval Level** | DRM / Empowered Committee |
| **Data Sources** | TMS (annual renewal programs), TDMS (OHE replacement schedules), SMMS (EI commissioning plans) |

**Key Behaviors:**
- AI generates the baseline 26-week schedule by allocating macro-level blocks for major works.
- Each week, the oldest week drops off and a new week is appended.
- Long-term diversions and cancellations are visible months in advance.
- Contractor bidding windows are aligned with strategic block allocations.

### Tactical Horizon — Monthly Refinement

| Attribute | Value |
|-----------|-------|
| **Time Span** | 4 weeks ahead |
| **Update Cycle** | Weekly review meetings |
| **Content** | Preventive maintenance (PINN-predicted), seasonal tasks, equipment calibration |
| **Approval Level** | Section Controller / ADRM |
| **Data Sources** | PINN RUL predictions, seasonal maintenance calendars, TMS TGI trends |

**Key Behaviors:**
- Inserts predictive maintenance tasks generated by PINN models.
- Accounts for seasonal variations (pre-monsoon drainage, winter rail tensioning).
- Fills remaining corridor space left by the strategic schedule.
- Validates against dynamic COA freight forecasts.

### Operational Horizon — Weekly / Daily Execution

| Attribute | Value |
|-----------|-------|
| **Time Span** | 7 days (weekly lock) → 24 hours (daily dynamic) |
| **Update Cycle** | Continuous (real-time recalculation) |
| **Content** | Acute repairs (IMR defects), ad-hoc blocks, emergency possessions |
| **Approval Level** | Section Controller (weekly), Station Master + Controller (daily) |
| **Data Sources** | Real-time COA train running data, TMS IMR alerts, live track circuit states |

**Key Behaviors:**
- Schedule is "locked" 48 hours before execution.
- IMR defects can **force-insert** into a locked schedule (safety override).
- Real-time freight delay monitoring triggers corridor recalculation.
- Ad-hoc block extensions or shifts proposed dynamically.

## Schedule Data Model

```typescript
interface Schedule {
  id: string;
  horizon: 'STRATEGIC' | 'TACTICAL' | 'OPERATIONAL';
  
  // Temporal
  weekNumber: number;           // ISO week
  year: number;
  startDate: Date;
  endDate: Date;
  
  // Content
  blocks: ScheduledBlock[];     // Ordered list of scheduled blocks
  corridors: Corridor[];        // Available corridors identified
  
  // Status
  status: 'DRAFT' | 'PUBLISHED' | 'LOCKED' | 'EXECUTED' | 'ARCHIVED';
  publishedAt?: Date;
  lockedAt?: Date;
  
  // Approval
  approvedBy?: string;
  approvalLevel: 'CONTROLLER' | 'ADRM' | 'DRM' | 'EMPOWERED_COMMITTEE';
  
  // Metrics
  totalBlockHours: number;
  shadowBlockUtilization: number;  // Percentage
  corridorUtilization: number;     // Percentage
  
  // Metadata
  version: number;              // Incremented on each revision
  createdAt: Date;
  updatedAt: Date;
}

interface Corridor {
  id: string;
  section: string;
  fromStation: string;
  toStation: string;
  startTime: Date;
  endTime: Date;
  durationMinutes: number;
  line: 'UP' | 'DOWN';
  
  // Computed
  isOccupied: boolean;          // Is a block scheduled in this corridor?
  occupiedBy?: string;          // Block ID
  remainingCapacityMinutes: number;
}

interface ScheduledBlock {
  blockId: string;
  corridorId: string;
  scheduledStart: Date;
  scheduledEnd: Date;
  department: string;
  isShadow: boolean;
  parentBlockId?: string;
  aiConfidence: number;
}
```

## API Surface

```typescript
export class SchedulingService {
  // Strategic
  static async generateRBP(startWeek: number, year: number): Promise<Schedule>;
  static async rollForward(): Promise<Schedule>;  // Append next week
  
  // Tactical
  static async refineMonthly(month: number, year: number): Promise<Schedule>;
  static async insertPredictiveTasks(predictions: RULPrediction[]): Promise<ScheduledBlock[]>;
  
  // Operational
  static async lockWeekly(weekNumber: number): Promise<Schedule>;
  static async recalculateDaily(date: Date): Promise<Schedule>;
  static async forceInsertIMR(imrDefect: IMRDefect): Promise<ScheduledBlock>;
  static async handleTrainDelay(delay: TrainDelay): Promise<ScheduleAdjustment>;
  
  // Queries
  static async getSchedule(horizon: Horizon, params: ScheduleQuery): Promise<Schedule>;
  static async getCorridors(params: CorridorQuery): Promise<Corridor[]>;
  static async getMetrics(params: MetricsQuery): Promise<ScheduleMetrics>;
}
```

### REST Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/schedules` | List schedules by horizon, date range |
| `GET` | `/api/schedules/:id` | Get schedule details |
| `POST` | `/api/schedules/generate` | Trigger AI schedule generation |
| `POST` | `/api/schedules/:id/lock` | Lock a schedule for execution |
| `POST` | `/api/schedules/:id/publish` | Publish schedule for review |
| `GET` | `/api/schedules/corridors` | Query available corridors |
| `GET` | `/api/schedules/metrics` | Get scheduling efficiency metrics |
| `POST` | `/api/schedules/recalculate` | Force recalculation (e.g., train delay) |

## Events

| Event | Trigger | Consumers |
|-------|---------|-----------|
| `schedule.generated` | AI produces new schedule | Block Planning, Notification |
| `schedule.published` | Schedule published for review | Approval Service, Notification |
| `schedule.locked` | Weekly schedule locked | Digital Twin, Block Planning |
| `schedule.recalculated` | Dynamic recalculation due to delay | Digital Twin, Notification |
| `schedule.imr_forced` | IMR defect force-inserted | Notification (alert all stakeholders) |

---

## Recalculation Trigger Matrix

| Trigger Event | Source | Recalculation Scope | Urgency |
|---------------|--------|---------------------|---------|
| Freight train delayed > 30min | COA | Affected corridors only | Immediate |
| IMR defect detected | TMS | Full daily schedule | Emergency |
| PINN predicts imminent failure | SMMS | Tactical (next 4 weeks) | High |
| Block duration extended by SSE | UI | Affected corridor + neighbors | Medium |
| Weather alert (monsoon) | External | Full weekly schedule | High |
